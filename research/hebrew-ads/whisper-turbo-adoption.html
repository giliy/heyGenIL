Hebrew Whisper Adoption

The one correction that shapes this plan

The verified candidate assumes we "point the whisperX backend at the model." The code says something more specific, and it changes where the work lands:

tools/align_words.py aligns captions with whisperX's wav2vec2 forced-align stage (load_align_model) — for --lang he whisperX resolves a Hebrew wav2vec2 aligner. The turbo Whisper model does not plug into that stage. It enters only through whisperX's transcribe stage (whisperx.load_model → faster-whisper) — which is the path tools/verify_consent.py already exercises, and exactly where the turbo detect-version bug bites.

Scope correction

So this is a fallback-lane upgrade, not a primary-path swap. The ad lane's primary word-timing source is edge-tts native boundaries; whisperX is the fallback. The real payoff is the TSX and AI-shorts lanes, where Hebrew ElevenLabs/kokoro audio currently aligns against a generic multilingual recognizer.

Ordered steps

  1. Install & pin the aligner env

    In the committed voice venv (.venv-voice312, Python 3.12 — not the stdlib core): pip install "faster-whisper>=1.2" "ctranslate2>=4.5", then pull ivrit-ai/whisper-large-v3-turbo-ct2 (the official ct2 conversion, Apache-2.0). CPU compute type int8. Validate pin drift against the existing whisperX install once.

  2. Apply the tiny detect-version shim

    whisperX's faster-whisper backend counts decoder layers and maps to a hardcoded dimension table; a 4-decoder-layer turbo model raises "Unable to detect model version." Add a ~2-line patch to whisperX's detect_version (map the turbo ct2 config → n_audio_state=1280) in a vendored shim module — not an edit inside site-packages, so the venv stays reproducible. Fallback if the shim proves brittle: run this one transcription through stable-ts, which handles ct2 turbo cleanly.

  3. Wrap: one deterministic transcribe helper

    Add a thin helper in align_words.py (lazy import, behind the existing importlib.util.find_spec("whisperx") guard — core stays stdlib-only): transcribe_he(audio_path) → word segments. Pin language="he", disable auto-detect, greedy decode (beam/best-of = 1, temperature = 0) for byte-determinism. Reuse verify_consent.py's existing precedent: decode 16k mono wav via ffw + soundfile, hand whisperX a numpy array, bypassing its bare-ffmpeg call.

  4. Integrate at the fallback boundary only

    In gen_voice.py:run_aligner, add an opt-in Hebrew branch: when lang == "he" and the ct2 model is cached, run the whisper recognizer first to produce/refine the transcript that whisperx.align consumes — replacing the generic multilingual recognizer on that path. Default behavior unchanged when the model is absent (degrades to estimated timing exactly as today). Do not touch the edge-tts primary path (gen_voice_edge.py); it already emits native word boundaries.

  5. Verify with a gated render

    One Hebrew TSX short end-to-end: render frames at phone scale, then run the existing sync gate (tools/sync_gate.py) and release gate (tools/release_gate.py). Pass criteria: (a) word boundaries are monotonic and within the gate's tolerance, (b) two identical runs produce byte-identical .words.json (determinism check), (c) no detect-version exception. Cache the model under media/library/ with a catalog entry if it's reused cross-video; per-video outputs stay in media/projects/<proj>/.

Open questions

  • Does whisperX's detect_version accept the turbo ct2 config with only the dimension-table entry, or does it also need a vocab/tokenizer hint? (Resolve in step 2.)
  • Is the vendored-shim approach acceptable to the reproducible-venv rule, or do we pin a whisperX fork? (Lean vendored; confirm.)
  • Does the accuracy gain justify routing verify_consent.py's Hebrew consent transcription through the same model as a second consumer? (Cheap to add later; out of initial scope.)

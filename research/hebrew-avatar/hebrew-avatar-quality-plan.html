Hebrew Avatar Quality Plan

Where the HeyGen-style Hebrew talking-avatar pipeline stands today, where the quality actually is, and how to raise it toward HeyGen for (almost) no money — with the lipsync and Hebrew-sync work front and center.

Where we are right now

The scaffold for a HeyGen-like product is already built and type-clean — CLI tools, a worker talk stage, database, APIs, a wizard UI, a spec-driven Remotion comp, and a spoken-Hebrew consent gate. The one thing missing: it has never rendered a single real frame. The entire lip-sync core is a dry-run; media/projects/_bakeoff-talk/ holds only a 13-second voice.mp3 and no video.

Three load-bearing facts the plan rests on, all adversarially verified against the code and live vendor pages:

  • Kling lipsync IS live on fal (fal-ai/kling-video/lipsync/audio-to-video, $0.014/s) — the older research claiming "not on fal" probed a malformed hyphenated URL and was wrong. The shipped registry is correct.
  • No phoneme/viseme data exists anywhere in the repo — timings stop at whole words. The lip-sync backends don't need it (they map audio→visemes internally), but any future custom sync driver would.
  • Avatar track is gated to the PRO tier (avatars_require_pro); talk billing is exactly 6× premium (4 vs 24 credits/sec).

The quality bar — what "HeyGen-good" actually is

The 2023–2026 literature is unambiguous that perceived realism is a full-face bundle, not lip-corner accuracy. Ranked by leverage:

  1. A task-matched, sync-trained audio encoder — beats both joint-trained and large Wav2Vec2 encoders (LSE-C 7.27 vs 7.12 / 7.22). This is the single biggest lever.
  2. Native 512×512 mouth-region resolution with explicit teeth/gum — not post-hoc upscale. Cheap lip-sync is recognizable precisely by a smeared mouth interior.
  3. Reference-Attention identity injection — not channel-concat or image embeddings.
  4. A temporal motion module — kills the single-frame jitter that single-step models (MuseTalk) admit to.
  5. Fixing identity-reference "lip leaking" — QA must test with identity frames whose mouth is not already near the target pose.

Where we can improve — the four gaps that matter

1. The lip-sync engine is un-chosen and un-proven

Two structural lanes exist and no single endpoint does both: photo→avatar (image+audio) and twin video→re-dub (video+audio). The decisive Hebrew fact: these models map acoustic features → visemes and never see text, so "supports Hebrew" means "its audio encoder wasn't English/Chinese-only." Whisper-encoder models (LatentSync, MuseTalk) inherit Whisper's 99-language coverage — which formally includes Hebrew. The Wan2.1-family (InfiniteTalk, MultiTalk) uses a Chinese-wav2vec2 encoder — the biggest Hebrew-quality risk.

Hebrew gutturals (ח/ע/ר) are UNVERIFIED in every published lip-sync paper. The nearest evidence (MuEx) covers Arabic pharyngeals and flags them underrepresented. Gutturals are largely pharyngeal with minimal lip articulation — actually easier for a sync model than rounded labials — but this is inference, not evidence. An empirical guttural-heavy Hebrew test set is non-negotiable and is itself the product's moat.

2. The Hebrew voice is intelligible but flat

The ivrit-ai TTS-Arena-Hebrew leaderboard (live pull) ranks paid cloud voices on top for Israeli ears — Deepdub (#1, Elo 1575), Google Gemini 3.1 Flash TTS (#2), ElevenLabs v3 (#3). Not a single free edge-tts/Azure he-IL voice or open model is on the board. The two edge-tts voices (he-IL-AvriNeural, he-IL-HilaNeural) are intelligible with trustworthy WordBoundary timings, but flat, single-energy, and Microsoft removed SSML — and edge-tts is a GPL/ToS risk for a paid product.

  • Code-switching Hebrew↔English is the defining failure mode — "mixed-language sentences are the real failure mode" (nisai.dev). QA must use real Israeli transcripts, not clean demo text.
  • Phonikud (INTERSPEECH 2026, CC BY 4.0) is the documented nikkud→IPA disambiguation layer — add it in front of any engine for ambiguous words.
  • Recommended ladder: default-free edge-tts → Azure direct for targeted phoneme fixes (F0 free 0.5M chars/mo, restores SSML) → ElevenLabs v3 for punchy ads (~$165–200/1M chars) → Gemini 3.1 / Deepdub for premium (no timestamps — pair with WhisperX) → free wildcard Chatterbox V3 + Phonikud (MIT, only commercial-legal free expressive Hebrew) pending a bakeoff.

3. Captions & RTL are a solved asset — keep them

Best free word-exact Hebrew timing = edge-tts WordBoundary first (already wired), WhisperX + imvladikon/wav2vec2-xls-r-300m-hebrew as fallback (~10–30 ms word jitter, fine for captions; MFA and Gentle are dead ends). RTL caption bugs come from skipped bidi + wrong base direction, not fonts: set dir="rtl", isolate embedded Latin/numbers with RLI…PDI, and keep Rubik (display) / Heebo (captions) — both SIL OFL 1.1, niqqud-safe.

4. No real sync QA gate exists

The plan called for a mouth-motion check but bakeoff_talk.py only asserts "the clip moved at all." A clip that moves but lip-syncs badly still passes. The fix is SyncNet: joonson/syncnet_python is MIT, current stack (Py 3.10 / torch 2.5.1 / CUDA 12.4). Gate on LSE-C ≥ ~6.9 (real-video baseline 7.6–7.9), hard-reject confidence < 3 (LatentSync's own cutoff), and always pair with a rendered-frame visual read at phone scale.

The plan — phased, near-zero budget

PHASE 0
$0 · 1–2 days
Fix the landmines + prove the core. This is the unlock — everything else waits on a real rendered frame.
  • Fix the kokoro-as-default-Hebrew landmine and the edge→kokoro fallback that silently swaps a broken Hebrew voice for an English one.
  • Fix live-portrait mislabeled as audio-input (it needs a driving video).
  • Set TALK_RESOLUTION=720p — kill the 480p→1080p upscale.
  • Add a SyncNet LSE-C gate to bakeoff_talk.py (replace motion-only).
  • Build the guttural-heavy Hebrew test set (a ח/ע/ר-dense newsreader script + a photo avatar).
  • Run the bakeoff: render the same Hebrew script through MuseTalk & LatentSync (self-host, ~$0 on a rented 4090 for an afternoon) vs fal Fabric/Kling/OmniHuman (~$5–10 of FAL credit). Judge at phone scale. Pick the winner per lane.
PHASE 1
<$20 · 1 week
Voice quality + pipeline hardening.
  • Add Phonikud G2P preprocessing for ambiguous/code-switched lines.
  • Bakeoff Chatterbox V3 + Phonikud (free, MIT) vs edge-tts with Israeli listeners — if it wins on expressiveness, it becomes the free default.
  • Move consent store out of in-memory (multi-process safe).
  • Per-line resegment in talk.ts (the deferred talkDir path) — enables re-rolling one line and per-scene camera variety.
PHASE 2
<$50/mo · 2–3 weeks
HeyGen-grade motion & self-serve editor.
  • If a rented 4090 (<$50/mo) beats hosted economics at your volume, migrate to self-hosted MuseTalk/LatentSync as the standard engine — $0.003–0.04 per 30s clip, 1–2 orders under fal.
  • Add the scene-based RTL script editor (the big net-new UI): script-first scenes, per-scene script segments, audio-only preview before spend (the HeyGen iteration funnel).
  • Add speed/pitch/pause controls and per-line emotion to the Hebrew voice picker.
PHASE 3
scale
Upscale & advanced. Prefer a generator that gives 512²+ mouth natively over upscaling a 256² face. When needed: GFPGAN (Apache-2.0, face) + Real-ESRGAN (BSD-3, background), with RealBasicVSR for temporal consistency. Then translation/dubbing (EN↔HE) and the Hebrew Video Agent.

Two decisions are yours, not the research's:

① Engine lane — self-host (cheapest at scale, you rent a GPU, you own MLOps + the Hebrew QA gate) vs. hosted fal/Replicate (fastest to ship, ~$1/30s, zero ops). My recommendation: prove quality on hosted first (Phase 0), migrate to self-host only when volume justifies the GPU box.

② Voice default — keep edge-tts (free, flat) vs. adopt Chatterbox+Phonikud (free, expressive, unproven) vs. pay ElevenLabs v3 (expressive, ~$165/1M chars). Recommendation: run the Chatterbox bakeoff; it's free and MIT-licensed, and if it wins it's the single biggest free quality jump available.

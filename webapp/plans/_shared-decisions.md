# Web App — Shared Decisions (read before any phase plan)

These are **locked cross-phase invariants**. Phase plans must not contradict them; they exist so six
independently-written plans assemble into one coherent product. Context: `WEBAPP-PLAN.md` (master plan),
this doc, and the repo engine. **Everything runs on localhost at this stage** — Docker for stateful
services, no cloud accounts required to develop. Ultracode session.

## Project spec (packages/spec) — the single source of truth
Superset of `beats.json`; both the Player (web) and `renderMedia` (worker) consume it as `inputProps`.
```ts
type Spec = {
  id: string; title: string; template: string; engine: 'tsx'|'ai';
  format: { width: number; height: number; fps: number };
  theme: { accent?: string; font?: string };
  voice?: { engine: 'kokoro'|'edge'|'elevenlabs'; voiceId: string;
            lines: { text: string; start: number; end: number; words?: {w:string;start:number;end:number}[] }[] };
  scenes: Scene[];                         // ordered; each == a beat
  captions?: { preset: 'pop'|'pill'|'fade'; burnIn: boolean; style?: Record<string,unknown> };
  audio?: { sfx?: { id: string; at: number; gainDb?: number }[]; music?: { id: string; duck?: boolean } };
  meta: { revision: number; updatedAt: string };
};
type Scene = {
  id: string; durationSec: number; beatId?: string; visual?: string;   // visual = template cue
  overlays: Overlay[];
};
type Overlay = {
  id: string; type: 'text'|'image';
  // text
  content?: string; style?: { font?: string; size?: number; color?: string; weight?: number; align?: string };
  // image
  assetId?: string; src?: string;      // src = resolved URL at render time
  // placement (composition px, 1080×1920) + SCENE-RELATIVE timing
  x: number; y: number; w: number; h: number; rotation?: number; opacity?: number;
  start: number; end: number;          // seconds within the scene (0..scene.durationSec)
  animation?: 'rise'|'fade'|'pop'|'none';
};
```
Invariants: overlay `start/end` are **scene-relative seconds** (never absolute) so scenes stay reorderable;
`meta.revision` increments on every persisted edit (conflict detection); durations/format derive from scenes via
`calculateMetadata` on the server. zod schemas in `packages/spec` validate every API payload + every job input
(this is the TS port of `tools/contracts.py`'s role).

## Templates & the engine contract (Phase 0's job)
- Each launch template = a parametrized composition exposing `defaultProps: Spec`-shaped props + `calculateMetadata`
  (durationInFrames from scenes). Launch set: **form-card (short-16) + one niche kit (terminal or chess)**.
- The worker bundles `remotion/` once per template+version and caches the `serveUrl`; renders with the same
  pinned headless-shell Chrome and `concurrency:'75%'` as `render-all.mjs`. Voice/captions come from
  `tools/gen_voice.py` (kokoro/edge free, elevenlabs paid) via the `.venv-voice312` interpreter.

## Storage
Default (dev): **local disk** — `webapp/.storage/<projectId>/<assetId>` served by the web app at
`/media/<key>`; the worker reads/writes the same dir via a shared volume/path (`STORAGE_DIR`). Optional
upgrade: MinIO in compose for real S3 presigned URLs behind `STORAGE_DRIVER=s3`. Interface is one module
(`packages/db`… actually `apps/web/lib/storage.ts` + worker equivalent) so S3 is a config swap later.

## Auth
**Auth.js v5 (next-auth) + Drizzle adapter + email magic link via MailHog** on localhost (no OAuth app setup
needed to develop; add Google later). Middleware protects `/dashboard`, `/editor`, `/api/*` (except auth +
job-status polling). `users` table above is the auth.js shape.

## Billing (Phase 4, still localhost)
Stripe in **test mode** + `stripe listen --forward-to localhost:3000/api/stripe/webhook`. Credit model:
`1 credit ≈ $0.01`; TSX render 2–4cr, AI image 3–5cr, AI voice line 1–2cr, AI video sec 6–8cr. Quote upfront
from the spec; **reserve at job submit, deduct on done, auto-refund on fail**; append-only `creditLedger`.
Free tier: watermark + 720p + monthly render quota + kokoro/edge voice + TSX only. Paid: 1080p/no watermark,
ElevenLabs, AI images, priority.

## Job flow (both types live in `jobs`)
- **render**: validate spec (zod) → quote credits → insert `queued` → worker claims (`FOR UPDATE SKIP LOCKED`
  or worker polls) → `running` with `progress` from `onProgress` → QA frames + audio_gate → upload output →
  `done` (+`outputKey`, +poster) | `failed` (+error, refund).
- **generate**: same table, `type='generate'`; `stage` walks `story→voice∥pixel→build→qa→mix`; writes a spec +
  assets, then a render job. The orchestration is a **port of `.claude/skills/orchestrate/`** to worker TS
  calling the python tools — same contracts, same gates (cost stated before paid pixels, audio_gate after mux).
- Progress UX: web polls `GET /api/jobs/[id]` every 2s (SSE is a later nicety). On `done` the dashboard card
  flips to ready with a playable/downloadable mp4.

## Definition of done (every phase)

- The phase's **exit artifact** is produced end-to-end (each phase ends in a rendered/downloadable video or a
  working feature slice).
- `npm run typecheck` + lint clean; unit tests for spec validators + job transitions; e2e smoke where stated.
- The plan file lists: goal · dependencies · exit criteria · data-model changes · API routes · UI · worker ·
  engine/remotion changes · env/compose · tasks (P0/P1) · risks · test plan · agent brief.

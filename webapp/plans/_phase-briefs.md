**Sequential gates:** 0 → 1 → 2 are strictly sequential (each needs the last). **3 and 4 both depend on
1/2** and are largely independent of each other — after Phase 2 lands, **Phases 3 and 4 can run in
parallel** (two agents) if you want. **5** is last.

## How to assign an agent
When you say "assign an agent to phase N":
1. I spawn an execution agent whose prompt = the **Agent brief** block from `phase-N-*.md` (already
   self-contained: context, invariants, ordered steps, exact verification commands, done-proof).
2. Because it's ultracode, the agent may use its own internal workflows/fan-out for the heavy build
   work, but **each phase is one assigned agent** owning the outcome and reporting back.
3. Sequential phases run one at a time; the independent pair (3, 4) can run in parallel after 2.
